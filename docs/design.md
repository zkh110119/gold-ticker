# Rust 实时金价 macOS Menu Bar 应用设计方案

## 1. 项目概述

开发一个常驻于 macOS 顶部菜单栏右侧的轻量原生应用，定时读取腾讯行情接口中的国际现货黄金报价，并在菜单栏与详情弹窗中展示当前价格、相对上次成功报价的涨跌、阈值状态与最后更新时间。

行情接口：

```text
https://qt.gtimg.cn/q=hf_XAU&_={timestamp}
```

其中 `{timestamp}` 替换为当前 Unix 毫秒时间戳，仅用于避免客户端或中间缓存返回旧响应；它不应被当作行情时间。

## 2. 目标与非目标

### 2.1 目标

- 启动后立即请求 `hf_XAU` 行情，之后以 **5 分钟**为默认周期刷新。
- 在 Menu Bar 显示紧凑行情，如 `Au 2,4xx.xx ▲ 2.15`。
- 点击菜单栏项目后显示彩色详情面板：最新价、涨跌额、涨跌幅、阈值、状态、最后成功更新时间。
- 用户可配置价格阈值、刷新周期和菜单栏展示精度。
- 高于或等于阈值显示红色；低于阈值显示绿色。
- 上涨、下跌与持平均可被颜色、箭头和文字/数值共同表达。
- 网络或接口失败时保留最近一次可信行情，明确显示数据过期状态。
- 所有价格运算使用十进制定点数，避免浮点比较误差。

### 2.2 非目标（MVP 不做）

- 不作为 macOS 桌面 Widget，也不实现 Dock 常驻窗口。
- 不保证金融交易级别实时性、准确性或可用性。
- 不执行交易、不提供投资建议、不保存账号或交易信息。
- 不在没有确认接口授权与稳定性的情况下公开商业分发。

## 3. 可行性与关键限制

### 3.1 Rust 可行性

Rust 可以实现网络请求、解析、刷新、缓存、配置与应用状态；界面通过 AppKit 的 Rust 绑定创建原生 `NSStatusItem`（菜单栏状态项）、菜单及 Popover。建议使用 `objc2` 家族绑定，而非用 WebView 或跨平台壳实现。

### 3.2 Menu Bar 颜色限制

macOS 顶部菜单栏上的状态项文本和模板图标会受浅色/深色、透明菜单栏与系统可读性策略影响，**不应依赖红绿文字在顶部菜单栏稳定呈现**。因此：

- 顶部菜单栏：显示中性色文本和上/下/平箭头，例如 `Au 2,485.16 ▲ 12.34`。
- 点击后的 Popover：可靠使用红色、绿色、图标与文字显示阈值状态及涨跌状态。
- 颜色不是唯一表达方式，始终保留 `▲`、`▼`、`—`、`高于阈值` / `低于阈值` 等信息。

### 3.3 腾讯接口的使用约束

该接口属于第三方行情端点。使用前必须自行确认其服务条款、调用频率限制、数据延迟、地域可用性、商业再分发授权和稳定性。客户端不能把它视为承诺 SLA 的生产金融数据源。

当前方案将响应解析与业务逻辑分离：一旦字段顺序或报价口径变化，可以只修改 Provider 映射或切换到授权 API，而无需重写 UI、缓存或阈值逻辑。

## 4. 数据口径

接口标识为 `hf_XAU`，产品 UI 必须从接口返回的字段确认后，明确标注以下内容：

| 信息 | 实现要求 |
| --- | --- |
| 品种 | 使用接口返回的名称/代码；初始配置为 `hf_XAU` |
| 币种 | 以实际响应为准，不得猜测或硬编码为 CNY/USD |
| 报价单位 | 以实际响应为准，例如金衡盎司或其他单位；必须在详情中显示 |
| 最新价 | 从已验证的响应字段读取 |
| 行情时间 | 使用接口内的报价时间；不可用时展示本地成功获取时间 |
| 涨跌基准 | 与上一条成功、同品种、同币种、同单位的本地报价比较 |

> 在首次实现时，必须保存一份经人工确认的真实接口响应样本，并为其建立解析测试。不要仅根据字段位置的猜测上线。

## 5. 用户体验设计

### 5.1 菜单栏状态项

默认紧凑文案：

```text
Au 2,485.16  ▲12.34
```

可选简洁文案：

```text
Au 2,485.16
```

| 状态 | 顶部展示 | Tooltip |
| --- | --- | --- |
| 成功且上涨 | `Au 2,485.16 ▲12.34` | 完整价格、涨幅、刷新时间、阈值状态 |
| 成功且下跌 | `Au 2,472.82 ▼-5.31` | 完整价格、跌幅、刷新时间、阈值状态 |
| 持平 | `Au 2,480.00 —` | 当前价无变化、刷新时间 |
| 加载中 | `Au 更新中…` | 正在请求最新行情 |
| 缓存/过期 | `Au 2,485.16 ·` | 上次成功获取时间；数据可能已过期 |
| 无数据 | `Au —` | 尚无可用行情；点击查看错误详情 |

### 5.2 Popover 详情面板

点击状态项后显示：

```text
国际现货黄金 · hf_XAU                         已更新 14:35

2,485.16 USD / troy oz
▲ +12.34  (+0.50%)

阈值：2,450.00                  当前高于阈值
数据源：腾讯行情                正常

[立即刷新]          [设置…]          [退出]
```

视觉规则：

- 当前价格依据阈值显示红色或绿色；等于阈值时按“高于或等于”处理，显示红色。
- 涨跌行根据方向显示对应色：上涨红色，下跌绿色，持平灰色。
- 若数据过期，显示灰色 `数据可能已过期` 标记，但不要将旧价伪装为最新价。
- 用语和价格格式根据实际币种/单位动态生成，避免将不匹配的 `$`、`¥` 或 `/g` 写死。

### 5.3 设置窗口

| 设置项 | 默认值 | 规则 |
| --- | --- | --- |
| 价格阈值 | 首次运行要求填写或使用建议默认值 | 必须为非负十进制数 |
| 刷新周期 | 5 分钟 | MVP 允许 5 / 10 / 15 / 30 / 60 分钟；不低于 5 分钟 |
| 菜单栏格式 | 完整 | 完整 / 简洁 |
| 小数位 | 自动 | 自动 / 2 / 3 / 4 位 |
| 启动时刷新 | 开启 | 可关闭 |
| 开机启动 | 关闭 | 后续版本可加入 `SMAppService` 支持 |
| 失败通知 | 关闭 | 后续版本；避免高频告警 |

## 6. 技术选型

| 层次 | 技术 | 职责 |
| --- | --- | --- |
| 语言与构建 | Rust stable + Cargo | 核心逻辑、构建管理 |
| macOS 原生 UI | `objc2`、`objc2-app-kit`、`objc2-foundation` | `NSStatusItem`、Popover、菜单、设置窗口 |
| 异步运行时 | `tokio` | 定时刷新、超时、任务协调 |
| HTTP | `reqwest` + `rustls-tls` | HTTPS 请求，避免 OpenSSL 依赖 |
| 解析 | `serde`（缓存/配置）+ 手写行情解析器 | 处理非标准 JavaScript 格式行情响应 |
| 金额计算 | `rust_decimal` | 价格、阈值和涨跌精确计算 |
| 时间 | `time` | 解析、过期判定与展示格式化 |
| 配置路径 | `directories` | macOS Application Support 路径 |
| 配置/缓存 | `toml` + `serde_json` | 用户设置与最后可信报价 |
| 日志 | `tracing` + `tracing-subscriber` | 可诊断日志，默认不输出敏感内容 |
| 测试 HTTP | `wiremock` 或本地 fixture | 稳定复现响应与异常情况 |

┌───────────────────────────▼────────────────────────────┐
│ App Controller                                          │
│ 生命周期、串行化 UI 更新、手动刷新防抖                  │
└─────────────┬───────────────────────────────┬──────────┘
              │                               │
┌─────────────▼─────────────┐   ┌─────────────▼──────────┐
│ Refresh Service            │   │ Settings & Cache        │
│ tokio 定时器 / 超时 / 退避 │   │ TOML / JSON / 原子写入  │
└─────────────┬─────────────┘   └────────────────────────┘
              │
┌─────────────▼──────────────────────────────────────────┐
│ MarketDataProvider trait                                 │
│ TencentGoldProvider / FixtureProvider / 后备 Provider     │
└─────────────┬──────────────────────────────────────────┘
              │ HTTPS GET

分层约束：UI 不直接发请求；Provider 不依赖 AppKit；领域计算不依赖网络、文件系统或 UI。这样便于替换数据源、编写测试和控制故障范围。

## 8. 腾讯接口接入设计

### 8.1 请求

```text
GET https://qt.gtimg.cn/q=hf_XAU&_={unix_milliseconds}
Accept: text/plain, */*
User-Agent: GoldTicker/0.1 (macOS)
```

请求规则：

- `{unix_milliseconds}` 使用本地当前时间，例：`1720000000000`。
- 不需要在 URL 中拼接 API 密钥；如未来换源，密钥只存 Keychain。
- 连接超时建议 5 秒，总请求超时建议 10 秒。
- 限制响应体大小，例如 64 KiB，避免异常响应占用过多内存。
- 不因失败而立即无限重试，遵守后文退避策略。

### 8.2 响应解析策略

该类端点常返回 JavaScript 变量赋值文本，而不一定是 JSON。解析器应使用下列防御性流程：

1. 将响应体按 UTF-8 解码；无法解码即视为失败。
2. 仅接受期望的变量前缀与标识，例如 `v_hf_XAU=`；不执行、`eval` 或注入响应中的任何 JavaScript。
3. 剥离变量赋值、引号与结尾分号，取得字段分隔字符串。
4. 将字段映射集中在 `TencentGoldProvider` 中，建立显式字段索引常量与说明。
5. 校验代码、价格、币种、单位、行情时间和数值范围；任一关键字段不符合预期则拒绝更新缓存。
6. 将原始响应只写入测试 fixture 或经脱敏的调试日志，生产日志不默认记录全文。

建议初始化阶段建立字段映射表：

| 内部字段 | 接口字段位置 | 状态 |
| --- | --- | --- |
| `symbol` | 待以真实样本确认 | 首次接入确认 |
| `display_name` | 待以真实样本确认 | 首次接入确认 |
| `price` | 待以真实样本确认 | 首次接入确认 |
| `currency` | 待以真实样本确认 | 首次接入确认 |
| `unit` | 待以真实样本确认 | 首次接入确认 |
| `source_timestamp` | 待以真实样本确认 | 首次接入确认 |

字段索引不应分散在 UI 或刷新代码中。若接口字段不提供币种/单位，则在供应商配置中以受版本控制的静态元数据补足，并在 UI 中明确标识其来源。

### 8.3 Provider 抽象

```rust
#[async_trait::async_trait]
pub trait MarketDataProvider: Send + Sync {
    async fn fetch_quote(&self, symbol: &str) -> Result<Quote, ProviderError>;
    fn name(&self) -> &'static str;
}
```

`TencentGoldProvider` 只负责构建 URL、请求、解析和验证，返回统一 `Quote`。未来新增授权数据源时，应用通过配置切换实现，不改变 UI 和核心计算。

## 9. 核心数据模型

```rust
pub struct Quote {
    pub symbol: String,
    pub display_name: String,
    pub price: rust_decimal::Decimal,
    pub currency: String,
    pub unit: String,
    pub source_timestamp: Option<OffsetDateTime>,
    pub fetched_at: OffsetDateTime,
    pub provider: String,
}

pub struct PriceChange {
    pub absolute: rust_decimal::Decimal,
    pub percentage: rust_decimal::Decimal,
    pub direction: Direction,
}

pub enum Direction {
    Up,
    Down,
    Flat,
}

pub enum DataFreshness {
    Fresh,
    Stale { age: Duration },
    Unavailable,
}

pub struct Settings {
    pub threshold: rust_decimal::Decimal,
    pub refresh_interval: Duration,
    pub menu_bar_format: MenuBarFormat,
    pub decimal_places: DecimalPlaces,
}
```

计算规则：

```text
absolute_change = current_price - previous_price
percentage_change = absolute_change / previous_price × 100
```

- 没有上一条有效报价、上一条价格为零、品种/币种/单位不相同时，不显示百分比及涨跌值，展示 `—`。
- 价格等于阈值视为“高于或等于阈值”。
- 对展示值而非原始值进行四舍五入；比较阈值使用原始 `Decimal` 值。

## 10. 刷新、缓存与失败策略

### 10.1 正常流程

1. 启动时加载 `Settings` 与最后成功缓存，并立即用缓存渲染 UI。
2. 并发触发一次请求；请求结束后在主线程更新 AppKit UI。
3. 成功响应通过校验后，与上一条同口径报价计算涨跌。
4. 使用临时文件写入，再原子替换缓存文件；随后更新界面。
5. 下一次计划刷新为成功后 5 分钟（或用户选定周期）。

### 10.2 失败处理

| 场景 | 用户可见行为 | 系统行为 |
| --- | --- | --- |
| 网络不可用 | 保留旧价，标为“可能过期” | 记录错误，延后重试 |
| HTTP 非成功 | 保留旧价与错误状态 | 不覆盖缓存 |
| 格式变更/字段无效 | 保留旧价，提示“数据解析失败” | 记录安全的诊断信息 |
| 超时 | 保留旧价 | 取消请求并退避 |
| 首次请求失败 | `Au —`，展示错误与重试入口 | 按退避计划重试 |

建议失败退避：`5 → 10 → 20 → 40 → 60` 分钟，上限 60 分钟；任意一次成功后重置为用户选择的刷新周期。手动刷新可以立即发起，但设置 15 秒防抖，避免重复点击造成接口压力。

数据新鲜度规则：超过 `2 × 刷新周期` 的最后成功数据为 `Stale`；超过 24 小时可显示“无近期数据”，但仍保留缓存供用户查看。

## 11. 本地存储与隐私

建议数据路径（由 `directories` 解析，不硬编码实际用户名）：

```text
~/Library/Application Support/GoldTicker/
├── settings.toml       # 非敏感用户偏好
├── quote-cache.json    # 最近成功报价与必要历史值
└── logs/               # 滚动诊断日志
```

- 当前腾讯接口无需密钥，不将任何凭据存入配置文件。
- 将来接入需认证的数据源时，凭据保存在 macOS Keychain，配置仅保存 Keychain 条目引用或 Provider 标识。
- 不上传用户阈值、配置、缓存或日志。
- 日志中不记录 Authorization、Cookie、密钥或未经审查的完整响应内容。

## 13. 测试计划

### 13.1 单元测试

- `Decimal` 价格的上涨、下跌、持平、零基数和不同精度计算。
- 阈值：低于、等于、高于；等于应为红色/高于状态。
- 品种、币种或单位变化时不得计算跨口径涨跌。
- 腾讯响应：正常样本、空响应、错误变量名、缺字段、非法数值、超长字段、非 UTF-8。
- 缓存：有效、损坏、旧版本迁移、写入中断后的恢复。
- 退避：连续失败递增、上限 60 分钟、成功后重置。

### 13.2 集成与手工测试

1. 启动时缓存价格立即可见，随后请求成功后更新。
2. 手动刷新只发送一次请求，连续点击受到防抖保护。
3. 实际接口可用时确认字段映射、货币、单位、行情时间和价格口径。
4. 切断网络、模拟 HTTP 失败、超时和异常响应后，应用不崩溃且 UI 显示过期/错误状态。
5. 分别在浅色与深色菜单栏下检查顶部文本可读性。
6. 在 Popover 中检查红绿颜色、箭头和文字含义一致。
7. 进行 24 小时运行测试，确认没有重复定时器、内存持续增长或 UI 线程阻塞。

## 15. 发布与合规

- 个人本地使用：可构建未签名 `.app`。
- 面向外部发布：通过 GitHub Releases 提供未签名、未公证的 `.dmg` 及 SHA-256 校验和；必须明确说明 macOS 会将其标识为未经验证，且不提供绕过系统安全保护的操作指引。
- 不发布 Mac App Store，也不配置 App Sandbox 或 App Store 审核所需的权限。
- 发布前再次确认第三方行情接口的授权范围，特别是展示、再分发、商业用途与调用频率。
- 产品界面应包含合适的免责声明，例如“仅供信息参考，非投资建议；行情可能延迟或出错”。

## 16. 关键决策与下一步

开始实现前，按优先级完成：

1. 用本地工具获取并保存一条真实 `hf_XAU` 响应，确认字段顺序和报价单位。
2. 确认腾讯接口对目标用途的授权与限频要求；若不满足，选择有明确授权的替代源。
3. 确认阈值的具体报价口径，例如与 `hf_XAU` 返回价格一致的币种与单位。
4. 以 P0 → P3 顺序实现 MVP，先验证数据和 UI，再考虑通知、开机启动、多数据源等扩展。
